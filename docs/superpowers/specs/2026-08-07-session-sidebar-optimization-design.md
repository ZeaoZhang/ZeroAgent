# 会话侧栏优化设计

**日期：** 2026-08-07
**状态：** 已获用户确认，待进入实现计划

## 目标

在不改变 ZeroAgent 现有颜色、字体、圆角、抽屉布局和整体交互风格的前提下，优化桌面前端左侧会话列表，使其适合大量会话的持续使用：

- 未分组会话默认按更新时间分组。
- 时间分组和用户分组都可以折叠。
- 用户可以创建、删除和管理自定义分组。
- 用户可以把会话拖入自定义分组。
- 键盘、触屏和不便使用拖拽的场景保留移动菜单作为兜底。
- 分组结构和会话归属可持久化，页面刷新、bridge 重启后不丢失。
- 组内会话继续按更新时间倒序，不增加组内手动排序。

## 现状与问题

当前桌面前端位于 `zero_agent/frontends/desktop/static`，状态和渲染主要集中在 `app.js`，会话数据通过 `desktop_bridge.py` 的 aiohttp bridge 获取和持久化。

已存在的实现可以按时间显示未分组会话，也可以创建分组、折叠分组、通过菜单移动会话，并在 bridge 中保存会话的 `group_id`。但仍有以下问题：

1. 时间分组只展示计数，不能真正折叠，箭头语义与交互状态不一致。
2. 分组名称、空分组和折叠状态主要依赖浏览器 `localStorage`；清理站点数据或换浏览器会丢失分组结构。
3. 分组 ID 直接使用名称，名称变更、重复名称和跨端同步的扩展性差。
4. 没有拖拽入组能力。
5. 每个会话常驻创建多个隐藏动作按钮。当前本地数据约有 284 个会话，页面会产生大量动作节点，影响 DOM 体积和无障碍树可读性。
6. bridge 启动时配置缺失 API key 会显示连接错误；本次设计不改变模型配置流程，但侧栏加载和数据失败必须有可见、可恢复的错误状态。

## 范围

### 包含

- 左侧会话列表的数据规范化、分组、排序和折叠渲染。
- 自定义分组实体的 bridge 持久化。
- 会话到分组的归属持久化和迁移兼容。
- 原生 HTML Drag and Drop 会话入组。
- 现有移动菜单的可访问性和错误恢复。
- 侧栏长列表的 DOM 和事件处理优化。
- 对应的前端 Node 回归测试、Python bridge 测试和浏览器 smoke 测试。

### 不包含

- 组内手动排序。
- 跨设备实时协同编辑。
- 会话搜索、标签、收藏、归档等新的信息架构。
- 右侧 agent 面板和主聊天区的视觉改造。
- 替换现有 Tauri/HTTP bridge 技术栈。

## 设计决策

### 1. 保留现有技术边界

继续使用原生 JavaScript、DOM、CSS、`za-web.js` RPC 适配器和 `aiohttp` bridge。侧栏新增一个内部的会话侧栏管理模块，负责把原始会话和分组数据规范化成渲染模型，隐藏排序、时间分桶、拖拽和回滚细节。

外部接口保持小而稳定：

- `loadSidebarData()`：从 bridge 加载会话和分组，并合并本地折叠偏好。
- `renderSessionSidebar()`：按当前状态生成侧栏 DOM。
- `moveSessionToGroup(sessionId, groupId)`：执行归属更新、持久化和失败回滚。
- `toggleSidebarSection(sectionId)`：切换并保存折叠状态。

具体函数名可按现有 `app.js` 结构调整，但调用方不应自行复制分组或排序逻辑。

### 2. 混合持久化

采用已确认的混合持久化策略：

后端持久化：

- 分组稳定 ID。
- 分组名称。
- 分组创建时间。
- 分组显示顺序。
- 会话的 `group_id` 归属。

浏览器本地持久化：

- 每个分组和时间桶的折叠状态。
- 仅影响当前浏览器的显示偏好，不影响数据归属。

推荐的后端数据形状：

```json
{
  "version": 2,
  "groups": [
    {
      "id": "group-<stable-id>",
      "name": "工作",
      "createdAt": 1720000000000,
      "position": 0
    }
  ]
}
```

`sessions.json` 继续记录每个会话的 `group_id`。分组实体和会话归属通过稳定 ID 关联；删除分组时先解除会话归属，再删除分组实体。删除分组不得删除会话。

### 3. 默认分组顺序和排序

侧栏顺序固定为：

1. 自定义分组，按后端 `position` 升序。
2. `今天`。
3. `昨天`。
4. `最近 7 天`。
5. `更早`。

没有内容的时间桶不显示。空的自定义分组仍显示，保证用户创建分组后有明确反馈。

所有会话在其所属分组内按 `updatedAt` 降序排列；缺少或非法时间戳时回退到 `createdAt`，再回退到稳定的原始顺序。时间分桶使用浏览器本地日期边界，不能用固定 24 小时差替代“昨天”的日期语义。

时间桶和用户分组使用同一套可折叠 section 接口：

- 标题是可聚焦的按钮。
- `aria-expanded` 反映展开状态。
- `aria-controls` 指向内容容器。
- 折叠时内容容器不参与布局和辅助技术树。
- 当前默认展开 `今天` 和 `昨天`，其他区段沿用已保存偏好或默认折叠。

### 4. 拖拽与菜单兜底

会话行设置 `draggable="true"`。拖拽生命周期：

1. `dragstart` 写入会话的 bridge ID 和本地 ID，给源行添加拖拽样式。
2. `dragenter`/`dragover` 仅对自定义分组标题调用 `preventDefault()`，并添加目标高亮。
3. `dragleave` 移除目标高亮，避免离开嵌套内容时错误闪烁。
4. `drop` 校验 payload、目标分组和会话存在性，调用统一的移动函数。
5. `dragend` 无论成功失败都清理源行和目标分组的临时状态。

拖拽目标只包括自定义分组，不允许把会话拖到时间桶中；未分组操作通过现有“移出分组”菜单完成。拖入当前所属分组视为无操作，不发送重复请求。

保留会话行的移动菜单，并确保：

- 使用真实按钮。
- 支持键盘焦点和 Enter/Space。
- 可选择现有分组、创建分组或移出分组。
- bridge 失败时恢复原归属并显示错误。

为减少长列表常驻 DOM，可将移动和删除动作收敛为一个单一的“更多操作”按钮；菜单打开后再创建动作项。若现有测试或视觉约束证明两个动作按钮更稳定，则至少保证动作节点使用事件委托，不能为每个会话绑定一组重复的全局监听器。

### 5. 错误处理和一致性

侧栏数据加载失败时：

- 保留已加载的本地会话，不清空用户当前列表。
- 展示与现有错误 banner 一致的可见错误。
- 允许重试，不静默吞掉 bridge 错误。

分组写操作使用乐观 UI 但必须可回滚：

- 保存旧的 `groupId` 和相关分组状态。
- bridge 成功后保留新状态并重新渲染。
- bridge 返回 404 时按会话不存在处理，并刷新会话列表，不能把错误归因于分组成功。
- 其他错误恢复旧状态并显示错误。

并发移动同一会话时，后发操作不得覆盖未完成操作的回滚信息。可以通过每会话操作 token 或复用现有 promise map 保证同一会话写入串行化。

分组存储迁移：

- 读取当前版本的旧 `localStorage` 分组元数据。
- 对旧的名称型 group ID，按名称匹配后端分组；匹配不到时生成稳定 ID 并完成一次迁移。
- 迁移期间不得丢失已有会话归属。
- 无法解析的分组记录只记录诊断并跳过，不阻塞侧栏加载。

### 6. 长列表渲染

首版不引入虚拟列表，避免破坏现有点击、拖拽、滚动和 DOM 缓存行为；先通过以下方式降低负担：

- 统一 section 渲染，减少重复节点。
- 用事件委托处理会话选择、更多操作和拖拽相关事件。
- 折叠区段不创建或不保留其会话内容节点。
- 避免在每次状态通知中为未变化的区段重复重建。
- 只对更新时间、归属或活动状态实际变化的列表执行重渲染。

如果 500+ 会话的浏览器 smoke 测试仍显示明显滚动卡顿，再单独设计虚拟列表，不在本次改造中预先引入。

## 文件职责

- `zero_agent/frontends/desktop/static/app.js`
  - 侧栏状态规范化、时间分桶、section 折叠、拖拽状态、移动回滚和 DOM 事件委托。
- `zero_agent/frontends/desktop/static/index.html`
  - 保持现有侧栏骨架；如需新增拖拽提示或统一操作菜单，只增加语义容器。
- `zero_agent/frontends/desktop/static/styles.css`
  - 在现有配色和尺寸基础上增加 section 展开状态、拖拽源/目标状态和长列表细节样式。
- `zero_agent/frontends/desktop/static/za-web.js`
  - 增加分组列表、创建、更新、删除所需的最小 RPC 映射。
- `zero_agent/frontends/desktop_bridge.py`
  - 提供分组实体加载、持久化、归属更新和删除分组时的原子解除归属。
- `tests/frontend_session_sidebar.test.js`
  - 覆盖纯前端排序、分桶、折叠、拖拽 payload、菜单兜底、移动回滚和长列表渲染契约。
- `tests/test_desktop_bridge.py`
  - 覆盖分组持久化、迁移、归属更新、删除分组不删除会话和 HTTP 路由。

## 验收标准

### 功能

1. 有效时间戳的未分组会话按本地日期进入四个时间桶，并在桶内按更新时间倒序。
2. 所有时间桶和自定义分组均可独立折叠，刷新后当前浏览器的折叠偏好保留。
3. 新建空分组立即显示，刷新和 bridge 重启后仍显示。
4. 会话可从时间桶拖入自定义分组，目标高亮、成功后归属变化可见。
5. 移动菜单可以完成拖拽的同等移动、创建分组和移出分组操作。
6. 删除分组只解除会话归属，相关会话回到时间桶。
7. bridge 重启或页面刷新后，分组名称、顺序和会话归属保持。
8. 旧版名称型分组数据迁移后不会丢失可识别的会话归属。

### 可用性与风格

1. 保持现有颜色、字体、圆角、侧栏宽度、按钮图标风格和主布局。
2. 展开、折叠、拖拽中、拖拽目标、保存失败和空分组都有清晰但克制的状态反馈。
3. 分组标题、会话行、操作菜单和确认对话框支持键盘访问。
4. 会话标题超长时不撑开侧栏；所有文字在容器内截断或换行符合现有规则。
5. 时间桶标题不再呈现“可点击但不可用”的误导状态。

### 性能与回归

1. 284 个以上会话可以完成初次渲染和滚动；不为每个会话重复绑定不必要的全局监听器。
2. 折叠区段不会继续渲染隐藏会话内容。
3. 现有会话删除、最后会话替换、消息 reconciliation 和 bridge 启动契约测试继续通过。
4. `node --check`、Node 前端回归测试、desktop bridge 测试和浏览器 smoke 场景全部通过。

## 验证方案

自动化：

- `node --check zero_agent/frontends/desktop/static/app.js`
- `node --check zero_agent/frontends/desktop/static/za-web.js`
- `node tests/frontend_message_reconciliation.test.js`
- `node tests/frontend_session_sidebar.test.js`
- `uv run pytest tests/test_desktop_bridge.py -q`，前提是项目测试依赖可用

浏览器 smoke：

1. 以认证 token 启动 bridge 并打开静态前端。
2. 验证真实会话按时间桶显示。
3. 折叠和展开时间桶、用户分组，确认内容和 `aria-expanded` 同步。
4. 创建空分组，拖动一个真实会话到分组标题，确认移动后列表位置变化。
5. 使用移动菜单完成一次移出分组。
6. 刷新页面，确认分组实体和会话归属保留，折叠偏好保留。
7. 删除分组，确认会话回到对应时间桶且会话仍存在。
8. 在 284+ 会话数据下观察列表滚动、动作响应和错误状态。

## 明确的后续边界

本设计完成后，下一阶段只执行上述范围内的实现计划。组内手动排序、虚拟列表和跨设备实时同步需要新的设计确认，不应在实现过程中顺带加入。
