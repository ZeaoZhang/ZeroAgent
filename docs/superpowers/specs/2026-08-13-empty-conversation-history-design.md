# 空对话历史过滤设计

**日期：** 2026-08-13
**状态：** 已确认，进入实现

## 目标

历史会话只保存和显示已经包含真实用户输入的对话。刚创建但尚未发送有效用户消息的会话只作为当前内存草稿存在。

## 判定规则

有效用户消息满足：`role == "user"`，且文本内容去除空白后非空。内容块格式取其中非空 `text` / `input_text`。系统、assistant、tool、错误消息不单独使对话进入历史。包含图片的规范化 prompt 会产生图片路径标记，因此仍视为有效用户输入。

## 方案

后端统一过滤并负责持久化边界：

- `AgentManager.create_session()` 只创建内存草稿，不立即把空会话写入 `sessions.json`。
- 首条有效用户消息通过 `add_message()` 后，`_persist_sessions()` 才写入该会话。
- `_persist_sessions()` 始终过滤无有效用户消息的会话，防止其他生命周期路径写入空记录。
- `_load_persisted_sessions()` 跳过旧版本中的空记录，并在发现后清理持久化文件。
- `/sessions` 只返回有效会话。

旧版日志历史同步过滤：

- `continue_cmd.list_sessions()` 只返回包含有效用户 prompt 的日志。
- `_snapshot_current_log()` 不为没有有效用户 prompt 的当前日志创建快照。

前端防御性过滤：

- 侧栏渲染只将包含有效用户消息的会话作为历史条目。
- 空会话仍可作为当前编辑容器存在；首条消息加入后立即显示在侧栏。

## 错误与兼容

空会话可以被删除、替换或分组操作，但这些操作不会使其进入历史存储。已有 `sessions.json` 中的空会话在启动时被忽略并清理；有效会话、分组实体和消息恢复逻辑保持不变。

## 验证

增加 Python 回归测试覆盖空创建、首条有效消息持久化、旧空记录清理和旧日志过滤；增加 Node 回归测试覆盖侧栏不显示空会话且显示有效用户会话。运行对应 pytest、Node 回归和语法检查。
